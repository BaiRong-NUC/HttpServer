Recent Updates

最近这次代码调整

这一轮主要围绕超时准确性、HTTP 路由匹配开销、业务线程池的归属层次，以及线程池自身的并发安全做了收敛。

Timer Wheel

修正 timerfd 累计超时计数

timerfd 每次 read 返回的是累计超时次数，不是固定的 8 次超时。现在时间轮按真实次数推进，30 秒非活跃回收恢复为按真实秒数触发。

图像恢复代理的连接超时也同步放宽到 600 秒，与 curl 的 10 分钟超时保持一致。

HTTP Routing

路由注册阶段预编译正则

Get、Post、Put、Delete 注册路由时就构造 std::regex，请求到来后只执行 std::regex_match。

这样把正则编译成本前移到启动阶段，减少高并发下每次请求重复编译带来的开销。

Business Pool

业务线程池上提到 TcpServer

TcpServer 构造时统一创建业务线程池，并在建立连接时传给每个 Connection。以后扩展自定义协议时，只要设置 message_callback 就能复用这套异步处理能力。

Thread Safety

只下沉业务回调，不破坏 Reactor 串行 I/O

没有把 EventLoop 的全部任务改成线程池执行，因为 Send、Close、EnableWrite、RemoveChannel 这类 I/O 状态操作必须留在连接所属 Reactor 线程。

现在只把 message_callback 投到业务线程池，投递前暂停读事件，处理完再切回原 EventLoop 恢复读；线程池则采用每个 worker 一把锁的桶式模型，而不是一个全局任务队列锁。

项目路径

/src/server 处理事件循环与连接

/src/server/tcp_server.cpp 统一创建业务线程池并分发到 Connection

/src/protocol/http/http_server.cpp 在路由注册阶段预编译正则

/build/lib 输出静态库与对外头文件

/build/app 作为业务运行目录，/build/app/log 保存日志与 PID 状态。

如何启动项目

在项目根目录执行以下命令完成构建。构建后会同步两类产物：build/lib 供手动链接，build/app 供直接运行： 

mkdir -p build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
# 或者：
./rebuild.sh

使用构建目录下的统一脚本启动、查看状态并停止整套服务： 

./build/app/loop.sh start
./build/app/loop.sh status
./build/app/loop.sh stop

上面的脚本会同时管理 C++ HttpServer 和 Python 模型服务；模型服务默认优先使用 conda 的 web 环境，日志和 PID 会写到 build/app/log。

如果只想把网络库给别人使用，直接分发 build/lib/libhttpserver.a 和 build/lib/include 即可。

更多信息请查看项目根目录的 README.md 与 app/serving/README.md。
